# 内容运营工作台

`dsh-media-workbench` 是面向单人运营的 DSH Desktop 工作台插件（Phase 1），管理官号视频、达人合作、发布排期及数据复盘。它复用 Harness 会话和公共侧栏，不替换市场、设置或会话系统。多人共享、权限管理和云端持续采集不属于当前版本。

v0.3.0 已在 Desktop 0.8.1 的隔离 Harness 中验证工作台内原生会话创建、切换和草稿隔离；需配合明确版本限定的宿主适配。未上架 npm 或市场。

## 四区工作台

工作台采用黑白、少装饰的 Notion 式界面，默认显示必要内容，详情按需展开。具备会话承载接口时，右侧直接显示真实 DSH 对话，新建和切换会话保持四区布局。

- 拖动区域标题到另一区域可交换位置；拖动区域之间的分隔线可调整大小。
- 每个业务窗口拥有独立标签页，tab 只切换当前窗口内的视图，不改变其他窗口，也不负责收起窗口。
- 点击窗口右上角的减号收起整个窗口，点击工作台顶部对应按钮恢复；DSH 会话窗口同样支持。其余可见窗口自动填充空位。
- 收起保留原有节点、会话和当前草稿；窗口收起状态、标签与布局保存在本机，刷新后恢复。未保存业务草稿不因此获得跨刷新保证。
- 资料列表默认仅显示标题、状态或平台粉丝，以及必要操作；更多字段和归档等操作在“详情”中。图表保留缺失和延迟提示，次要筛选与数据解释可展开查看。
- 使用“新增看板”增加业务视图，并在该区域切换或比较数据。看板共享同一份业务记录，新增视图不会复制选题或发布数据。
- 会话绑定跨业务标签保留；从选题或 Campaign 新建、继续会话时使用真实 Harness 会话。切换后业务视图继续保留。

嵌入模式依赖宿主提供 `conversationHost`、`claimConversationHost(id)` 和 `renderConversation()`。v0.3.0 自动检测接口；缺失时禁用新建并显示宿主待适配，仅明确点击“退出工作台并打开普通对话”才离开。Desktop 0.8.1 的版本校验、安装和回退见 [宿主适配说明](../../docs/conversation-host-bridge.md)。这些是过渡接口，不能视为上游正式 SDK。

## 六个面板

| 面板 | 当前能力 |
| --- | --- |
| 选题面板 | 新建、编辑、归档、搜索及四状态筛选；记录出镜人、制作人、Campaign 和整体排期 |
| 营销日历 | 月历展示官号选题与达人交付；拖动整个选题修改计划时间，也可通过编辑表单改期 |
| 达人池 | 联系方式、平台账号、粉丝、参考报价；CSV/TSV 或飞书表格粘贴预览导入 |
| Campaign 项目 | 活动日期、预算、关联官号选题和达人交付；按发布记录的实际费用汇总 |
| 数据监控 | 五个平台发布链接、视频/文章形式、实际费用、实际发布时间；当前/24h/72h 快照和手动补录 |
| 每日成果 | 按天记录下载量、新增 GitHub Star、加群人数、线索人数；展示已记录日期的趋势 |

选题状态为 `unselected`（未选中）、`scheduled`（已排期）、`produced`（已完成制作）、`published`（已发布）。官号按视频选题组织，同一选题的各平台发布分别建记录。达人合作可记录视频或文章。选题排期和每个平台实际发布时间分开保存，拖动日历不重写实际发布时间。

达人参考报价 `quote` 与发布实际费用 `cost` 是两种数据。跨平台套餐需将费用分摊，或仅在一个交付记录中填写总费用，避免 Campaign 重复汇总。

## 本地开发

在独立仓库根目录使用 Node.js 22 或以上版本，安装开发依赖后启动：

```sh
npm install
npm run dev:media
```

打开 `http://127.0.0.1:4317/`，会跳转到 `/api/media-workbench/app`。该独立入口提供相同四区布局、区域拖动、业务面板和本地 API 预览，右侧会话区显示说明空态，不包含真实 DSH 会话。会话按钮会提示回到 DSH Desktop；验证原生对话需使用带上述 ui-layout 补丁的 DSH 宿主。

可以指定单独的数据目录和端口：

```sh
MEDIA_DATA_DIR=/tmp/dsh-media-development MEDIA_PORT=4318 npm run dev:media
```

默认开发数据目录是启动目录下的 `doc/media-workbench-dev/`。请将测试数据与正式数据分开，不要让两个进程同时写同一个目录。

基础检查：

```sh
npm --prefix packages/dsh-media-workbench run check
```

## DSH 插件接入与安装

先阅读仓库的 [插件管理机制](../../docs/plugin-management.zh.md)。npm 包、Profile Bundle、Cordis Entry、前端模块及 UI Slot 是不同层级，单纯复制文件或添加 npm 依赖不代表工作台已经启用。

本包已声明：

- `dsh.bundle.patch` → `cordis.patch.yml`，插入 `dsh-media-workbench` Entry。
- `./client` → `client.js`，声明所需的 Harness 客户端依赖。
- 服务端注入 `connection`、`tools`、`agents`，通过宿主连接提供 API。
- 前端使用 `sidebar.footer.action` 和 `shell.overlay` 扩展点，保留 DSH 公共入口。

在仓库根目录执行 `npm run pack:plugin` 生成包含宿主适配脚本的分发包；在**隔离的开发 Profile** 中按上述机制配置依赖和 `dsh.profile.bundles`，再检查 Entry、前端模块、侧栏入口是否全部加载。正式安装应走目标 DSH 版本支持的插件安装流程，遵守 immutable generation 管理；不要手工覆盖正在使用的生产 generation。本说明不表示该包已发布到 npm 或市场。

本包附带 [运营 Skill](skills/media-operations/SKILL.md) 作为 Agent 操作说明；实际工具由宿主插件按会话绑定注册，不依赖把 Skill 文本当作权限授予。

## 会话绑定

一个工作台对应多个会话，每个绑定会话只有一个主要归属：工作台、选题或 Campaign。同一选题和 Campaign 可以拥有多个会话。侧栏进入工作台后可恢复可用的最近会话，并在常驻会话区域继续讨论，同时查看其他区域的业务面板。

从工作台面板新建或继续会话，由父级 Harness 创建/恢复会话并保存绑定。切换业务面板不会重设归属；会话绑定不能直接转移至另一个对象。业务记录独立持久化，删除聊天不会删除选题、交付或快照。会话已删除时需要新建会话，已有业务记录仍保留。

`media_workbench_read` 和 `media_workbench_update` 只注册到已绑定会话；服务端执行时再次核验当前 Agent 的绑定。首版 Agent 只记录、分析和整理，不自动发布或生成营销内容。工作台归属与项目文件夹是不同概念；当前绑定会话会使用本插件数据根目录作为工作区路径。

切换面板或返回普通会话不停止宿主采集计时器；退出宿主、卸载插件或关闭采集浏览器会影响采集。

## 数据与备份

安装态默认目录：

```text
$DSH_HOME/workbenches/media/
├── state.json     # 业务记录、快照及会话绑定
└── browser/       # 独立 Chrome 采集配置及登录状态
```

未设置 `DSH_HOME` 时默认 `~/.dsh/workbenches/media/`。Cordis 配置项 `root` 可指定其他目录；开发启动使用 `MEDIA_DATA_DIR`，与安装态配置不同。

`state.json` 使用版本号、修订号和原子替换写入；同进程串行处理写操作，不提供跨进程锁或多人同步。损坏文件会报错，不会被自动清空重建。

顶部“导出数据”下载当前 JSON，可用于业务备份，包含达人联系人、费用和会话 ID，不包含 Chrome 登录状态。完整目录备份应先停止对应运行实例。恢复时先备份当前目录，再在停止实例后替换 `state.json`，保持结构和引用完整；目前没有一键恢复界面。恢复到其他 Harness Profile 后，旧会话 ID 可能不可用，需要重新创建绑定会话。

归档不会物理删除记录。快照只追加，人工修正需要新增快照。不要将 `browser/` 登录状态目录上传到公共仓库。

## 手动输入与 API 底座

所有平台均可以手动输入发布链接及指标，自动采集失败不会阻止手动工作。空白指标保存为 `null` 或缺失，不能推断为零；观看与文章阅读分别记录。每日成果是按天新增量，不是单条内容的因果归因。

所有路径都由同源宿主提供：

| 路径 | 方法与用途 |
| --- | --- |
| `/api/media-workbench/state` | GET：完整状态和当前采集运行信息 |
| `/api/media-workbench/mutate` | POST JSON：业务增改、归档、达人批量导入；会话绑定供宿主桥接使用 |
| `/api/media-workbench/export` | GET：业务 JSON 导出 |
| `/api/media-workbench/context?sessionId=...` | GET：读取有效绑定上下文 |
| `/api/media-workbench/browser/open` | POST `{}`：打开独立采集 Chrome |
| `/api/media-workbench/collect` | POST `{"publicationId":"实际记录ID"}`：尝试采集当前快照 |

增改示例（`expectedRevision` 必须替换为刚读取的实际修订号）：

```json
{
  "action": "upsert",
  "entity": "topics",
  "expectedRevision": 0,
  "data": { "title": "新功能演示视频", "status": "unselected" }
}
```

编辑时将 `id` 放在命令顶层；不要放进 `data`。删除采用 `action: "archive"`。达人批量导入采用 `action: "importCreators"`、`entity: "creators"`、`rows: [...]`。编辑与 Agent 使用相同底层模型；修订冲突后重新读取并核对改动，不能盲目覆盖。

本机服务不是多用户服务或公网认证 API，不应直接暴露给外网。

## 浏览器自动采集：实验能力

当前仅对 B站、小红书提供实验性的可见页面采集。抖音、微信公众号和视频号使用手动指标录入；达人资料导入目前是 CSV/TSV，并非飞书实时同步，也没有通用指标报表文件导入界面。

使用步骤：

1. 本机安装 Google Chrome，在数据监控中点击“打开采集浏览器”。
2. 如平台要求登录，由用户在独立 Chrome 窗口完成登录。
3. 给发布记录填写 B站或小红书含作品 ID 的完整 HTTPS 作品链接，点击“尝试自动采集”；短链接需先在浏览器展开，再填写实际作品 URL。采集器核对最终页面作品 ID 与输入 ID 一致，跳转到其他作品时不保存指标；失败时查看提示并手动录入。

插件使用 `playwright-core` 和专用持久浏览器目录，不读取其他 Chrome Profile 的 Cookie，不处理或绕过验证码，不点击点赞、评论或发布控件。页面改版、登录状态、异步加载和平台限制均可能导致部分或全部指标不可得。缩略数值（如“1.2万”）不当成精确快照存入。

自动留存每分钟检查已发布记录中到期且尚无快照的 `24h`、`72h` 节点。**电脑必须开机且醒着、网络可用、宿主进程运行，并保持采集浏览器开启。** 这不是云端任务，也不会保证精确到点执行。“当前”可通过手动触发采集刷新，不代表实时推送。

快照同时记录目标时间 `targetAt` 和实际采集时间 `capturedAt`。晚录入链接或停机错过节点后，只能记录恢复时观察到的数据，不会还原缺失历史。复盘时必须比较这两个时间，标注延迟，不得将晚到快照描述成准确的发布后 24/72 小时数据。

抖音当前未启用自动指标写入：页面邻接数字不足以稳定确认属于目标作品，手动录入作为保底。

已提供 B站、小红书实验采集及失败退路，但未完成这两个平台在各种登录状态、长时间运行及真实发布节点上的端到端可靠性验证。不要据此承诺采集成功率或生产可用性。
